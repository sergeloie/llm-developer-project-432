## Что это

Сервис принимает документы поставщиков (pdf, docx, xlsx), строит по ним поисковый индекс
и генерирует **черновик** карточки товара: с указанием источников, списком недостающих
данных и уровнем уверенности. Ключевое свойство черновика — каждая характеристика
указывает фрагмент документа, откуда взята, а чего в документах нет, попадает в
`missing_fields` вместо выдуманного значения.

Учебное задание курса, шаги 1–10. Контракт поведения — раздел «Результат шага»
в каждом шаге задания.

## Запуск

```bash
cp .env.example .env   # вписать адрес своего OpenAI-совместимого сервера моделей
make infra             # postgres с pgvector + temporal, оба с healthcheck
make setup             # зависимости + миграции
make api               # http://localhost:8000
make worker            # воркер устойчивых процессов
```

Проверка: `curl localhost:8000/health` (процесс жив) и `curl localhost:8000/ready`
(база доступна, расширение `vector` активно).

## Разработка

```bash
make test     # pytest
make lint     # ruff
make eval     # метрики генерации на золотом датасете (FULL=1 — весь датасет)
make reindex  # досчитать эмбеддинги для чанков без векторов
```

## Структура

```text
app/
├── main.py            приложение и сквозной request_id
├── core/              конфигурация, база, логи, раннер миграций
├── routers/           HTTP: cards, jobs, documents, generate, workflows, health
├── services/          сценарии: пайплайн генерации, RAG-пайплайн, контракт результата
├── agents/            промпты extractor, generator, critic
├── llm/               клиент модели и учёт стоимости вызовов
├── rag/               эмбеддинги, поиск, сборка контекста
├── parsers/           pdf, docx, xlsx, нормализация, чанкинг
├── guardrails/        PII и детектор инъекций
├── repositories/      SQL — только здесь
├── schemas/           контракты между слоями
└── temporal/          процессы: разбор, карточка, модерация
db/migrations/         SQL-миграции
evals/                 прогон метрик на золотом датасете
tests/                 тесты
data/                  документы поставщиков и золотой датасет
docs/adr/              принятые архитектурные решения
```

## Правила проекта

- SQL живёт только в `app/repositories/`. Воркеры, роутеры и сервисы не пишут запросов.
- К модели обращаются только через `app/llm/client.py`. Провайдер не знает ни один сервис.
- Соединение берётся на операцию (`app/core.db.connection()`), а не на весь шаг процесса.
- Код workflow-процессов детерминирован: без datetime.now / random / HTTP / чтения конфига.
- Комментарии в исходном коде не пишутся.
