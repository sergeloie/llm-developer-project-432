# Запросы к базе пишем руками, ORM не берём

## Контекст

Основная работа с базой в этом сервисе — векторный и полнотекстовый поиск по чанкам
документов. Гибридный режим сливает два ранжированных списка по формуле Reciprocal Rank
Fusion.

## Решение

Доступ к базе — psycopg, SQL пишется руками и живёт только в репозиториях. Соединения
берутся из пула, созданного на старте приложения.

## Альтернативы

SQLAlchemy с ORM, SQLAlchemy Core с сырым SQL через `text()`.

## Почему

Запрос гибридного поиска — это две подзапроса с `ROW_NUMBER()`, оператор `<=>` из pgvector
и `ts_rank`. ORM такой запрос не выражает, а через `text()` мы получили бы SQLAlchemy
ради пула соединений. Фоновая обработка идёт блокирующими шагами процесса, которые
движок исполняет в пуле потоков, поэтому асинхронная сессия потребовала бы своего
цикла событий в каждом шаге.

## Компромиссы

Схему приходится держать в голове и в миграциях, автоматических связей между таблицами
нет. Экранирование параметров — ответственность репозитория.

## Когда пересматривать

Если обычных сущностей станет заметно больше, чем векторного поиска, или если поиск
уедет во внешний индекс.
