# Миграции — обычные .sql и маленький раннер, ORM не берём

## Контекст

Схема базы задаёт то, ради чего сервис и написан: векторный поиск по pgvector,
полнотекстовый поиск по tsvector и гибридное слияние результатов. Плюс
`schema_migrations`, чтобы версия схемы была видна в самой базе, и `llm_calls`,
`jobs`, `documents` — обычные таблицы.

## Решение

Миграции — файлы `db/migrations/NNN_имя.sql`, которые по порядку имени применяет
раннер `app/core/migrate.py`. Каждый файл выполняется в своей транзакции вместе
с записью его версии (имя файла без расширения) в `schema_migrations`; уже
применённые версии повторно не выполняются. Схему применения и откат пишет
человек руками.

## Альтернативы

Alembic, миграции Django, миграции на SQLAlchemy, Flyway, Liquibase.

## Почему

Дальше по шагам в SQL идут вещи, которые DSL миграций либо не выражает, либо
выражает через строку с SQL внутри — то есть обратно в plain SQL, только с
обвязкой: индекс HNSW `USING hnsw (embedding vector_cosine_ops)`, генератор
`tsvector ... GENERATED ALWAYS AS (to_tsvector('russian', text)) STORED`, два
подзапроса с `ROW_NUMBER()` и оператор `<=>` в гибридном поиске. Alembic дал бы
autogenerate и версии, которых здесь не нужно: файлы пишутся руками и в любом
случае ложатся в git рядом с кодом, который их требует. Отдельный инструмент
ради шести файлов — это ещё одна зависимость и ещё одно место, где молча
расходится версия схемы с репозиторием.

## Компромиссы

Отката миграции нет: `downgrade` пришлось бы писать и поддерживать вручную, а
исправлять ошибку можно новым файлом. Скрипт не понимает ветвление и слияние
веток — версия это имя файла, и переименование уже применённого файла раннер
примет за новую миграцию. Порядок применения задаётся сортировкой имён, поэтому
префикс с номером обязателен. Всё это осознанно: цена ошибки в миграции
ниже, чем цена расхождения её с рукописным SQL в репозиториях.

## Когда пересматривать

Если миграции станут писать не разработчики приложения, а выкатывающий код с
несколькими параллельными ветками релизов, или понадобится откат версии
схемы на развёрнутом окружении — тогда стоит взять инструмент с ветвлением и
обратными миграциями. Пока схема меняется вместе с кодом и применяется на
стенде, список миграций на два десятка файлов дешевле переносить вручную.
