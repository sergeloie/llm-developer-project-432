# Оркестрация в коде, базовая среда OpenAI Agents SDK

## Контекст

Нужен бэкенд на Python, который принимает документы поставщиков, ищет по ним факты и
собирает карточку товара по строгой схеме. Требуются типизированные контракты,
тестируемая бизнес-логика, репозитории, поиск по документам и наблюдаемость. Поддерживать
сервис будет команда разработки, а не команда эксплуатации.

## Решение

Пишем оркестрацию кодом. Базовая среда — OpenAI Agents SDK: он берёт на себя цикл работы
агента, вызов инструментов и результат по схеме, оставляя логику приложения в Python.

## Альтернативы

Готовая платформа (Dify), low-code оркестратор (n8n), LangChain, LangGraph, Pydantic AI,
собственный цикл без SDK.

## Почему

Платформа и low-code сильнее там, где задача — связать много внешних систем силами
эксплуатации; здесь же ценность в внутреннем устройстве приложения. Машины состояний и
долгих графов в первой версии нет, поэтому LangGraph избыточен. Собственный цикл пришлось
бы писать вместе с инструментами, подтверждениями и трассировкой.

## Компромиссы

Появляется зависимость от SDK. Совместимость провайдера по API не гарантирует
одинаковую поддержку вызова инструментов и результата по схеме — возможности выбранного
сервера моделей проверяются отдельно.

## Когда пересматривать

Если центральной сложностью станет состояние графа или устойчивый процесс — вернуться к
LangGraph или движку устойчивого выполнения. Если цикл останется минимальным и SDK
окажется лишней абстракцией — оценить собственную оркестрацию. Если критичнее станут
типобезопасность и независимость от провайдера — сравнить Pydantic AI.
