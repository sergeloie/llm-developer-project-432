# Порог релевантности retrieval — 0.35

## Контекст

Гибридный поиск (`app/rag/retrieval.py`) отдаёт чанки по косинусному сходству
эмбеддингов. Порог отсечения `RETRIEVAL_THRESHOLD` действует только на
векторную ногу гибрида. Для генерации по **явно заданным документам** порог не
используется вообще — берутся все чанки документа (`retrieve_context_async` в
`app/services/rag_pipeline.py`), поэтому порог влияет только на поиск по
свободному запросу (`mode="hybrid"`).

История вопроса: порог понижали с 0.35 до 0.25, чтобы не терять спецификацию
(баг с `heater_passport`: similarity-top-k отбрасывал до 75% текста, и модель
достраивала карточку из имени файла). Позже баг устранён на уровне пути
генерации (все чанки документа берутся без порога), а поведение порога
замерено на реальном корпусе поставщиков
(`docs/retrieval-threshold-measurement.md`).

## Решение

`RETRIEVAL_THRESHOLD = 0.35`. Порог — настраиваемая переменная окружения
(`settings.retrieval_threshold`, `app/core/config.py`), значение по умолчанию
0.35, а не захардкожено в коде поиска.

## Почему

Замер на 60 запросах по реальному корпусу показал, что чистота топ-K стабильна
(~0.91 гибрид / ~0.99 вектор) во всём диапазоне 0.0–0.4 и падает только на
0.4→0.5, когда отсекаются релевантные чанки. 0.35 — середина этого стабильного
плато: внутри него значение порога на выдачу не влияет, но 0.35 отсекает хвост
мусора, который порог 0.25 ещё пропускает (граница чужого семейства по косинусу:
медиана ~0.47, минимум ~0.37). Чистого разделителя между «своим» и «чужим»
семейством нет, поэтому поднимать порог выше ~0.4 бессмысленно — режет
релевантное. Остаточные ~9% примеси в гибридной выдаче даёт FTS-нога (OR-семантика
`plainto_tsquery`), а не порог.

## Альтернативы

- 0.25 — промежуточное решение в пользу recall; замер показал, что на плато
  выдача не отличается, а мусорный хвост (<0.35) впускается.
- Поднять выше 0.4 — режет релевантные чанки (наблюдается на замере: 0.5 →
  чистота 0.85/0.79).
- Убрать порог и брать топ-K — теряется фильтрация мусора, который и так
  попадает в топ-K при коротких документах.

## Компромиссы

Ниже порога — больше шума в контексте и выше расход токенов на генерацию.
Если сменится эмбеддинг-модель или её размерность (`EMBED_DIM`), порог надо
пересматривать вместе с ней.

## Когда пересматривать

При смене `EMBED_MODEL` / `EMBED_DIM`, при росте доли карточек `needs_review` по
причине низкого покрытия источников (значит, спецификация снова не попадает в
контекст) или при появлении шума в сгенерированных карточках (значит, порог
пропускает мусор).
